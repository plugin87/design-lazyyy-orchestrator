# รายการตรวจก่อนบอกว่าเสร็จ — Definition of Done

| รายการ | รายละเอียด |
|---|---|
| งาน | [รหัส story / ชื่อ] |
| ผู้ทำ | [ชื่อ] |
| branch | [ชื่อ branch] |
| วันที่ตรวจ | YYYY-MM-DD |

ประตูขาออกของระยะพัฒนา ทุกข้อต้องติ๊กจริง ไม่ใช่ติ๊กเพื่อให้ผ่าน
ข้อที่ข้ามต้องเขียนเหตุผล ไม่ใช่เว้นว่าง

---

## เกณฑ์การยอมรับ

- [ ] เกณฑ์การยอมรับทุกข้อสาธิตให้เห็นได้ว่าผ่าน
- [ ] ครอบคลุมเส้นทางที่ผิดพลาดอย่างน้อยหนึ่งเคส
- [ ] กรณีทดสอบใน `TST-XXX-001` ที่เกี่ยวข้องผ่านครบ

## การทดสอบ

- [ ] มีเทสต์สำหรับพฤติกรรมใหม่ และเทสต์นั้นจะพังถ้าเอาโค้ดออก
- [ ] เทสต์ทั้งชุดผ่าน ไม่ใช่เฉพาะที่เพิ่งเขียน
- [ ] ไม่มี error หรือ warning ใหม่ใน console

## ส่วนติดต่อผู้ใช้ — ข้ามได้ถ้างานไม่มีหน้าจอ

- [ ] ใช้คีย์บอร์ดเข้าถึงและใช้งานได้ครบ มีขอบโฟกัสที่มองเห็น
- [ ] ใช้ design token ไม่ใช่ค่าที่ฮาร์ดโค้ด
- [ ] แสดงผลถูกต้องในทุก breakpoint ที่ประกาศไว้
- [ ] สถานะครบ — ว่าง กำลังโหลด ผิดพลาด ไม่มีสิทธิ์

## เอกสารและการสอบทาน

- [ ] ตารางสอบทานย้อนกลับระบุแล้วว่าโค้ดนี้ทำตามข้อกำหนดข้อไหน
- [ ] เอกสารที่อธิบายพฤติกรรมนี้ถูกปรับให้ตรงกับของจริงแล้ว
- [ ] สมมติฐานและคำถามที่ยังค้าง บันทึกไว้ใน `project.yml` แล้ว
- [ ] ข้อขัดแย้งในเอกสารต้นทางที่พบ ออกเป็นคำขอเปลี่ยนแปลงแล้ว

## ก่อนส่งให้ทบทวน

- [ ] อ่าน diff ของตัวเองทั้งหมดเหมือนเป็นงานของคนอื่น
- [ ] ไม่มีโค้ดทดลอง ไม่มี `console.log` ที่ลืมไว้ ไม่มีไฟล์ที่ไม่เกี่ยวข้อง
- [ ] commit แต่ละอันเป็นเหตุผลเดียว แยกเรื่องที่ไม่เกี่ยวกันออกจากกันแล้ว
