# รายการตรวจก่อนปล่อยของ

| รายการ | รายละเอียด |
|---|---|
| สิ่งที่จะปล่อย | [commit / tag / artifact — ระบุให้ชี้กลับได้] |
| ปล่อยขึ้นที่ไหน | [สภาพแวดล้อม] |
| ผู้ตัดสิน | [ชื่อ] |
| วันที่ตรวจ | YYYY-MM-DD |

ข้อที่ข้ามต้องเขียนเหตุผล ไม่ใช่เว้นว่าง · ข้อที่ตอบไม่ได้ = NO-GO ไม่ใช่ GO แบบมีข้อแม้

---

## 1. ประตูก่อนหน้าผ่านแล้ว

- [ ] รายงาน QA มีอยู่จริง และคำตัดสินไม่ใช่ `BLOCK`
- [ ] การทบทวนโค้ดไม่มี `REQUEST CHANGES` ค้างอยู่
- [ ] ข้อค้นพบระดับ BLOCKER ทุกข้อปิดแล้ว ไม่ใช่เลื่อนออกไป

## 2. สิ่งที่จะปล่อยระบุตัวได้

- [ ] รู้แน่ชัดว่าปล่อย commit หรือ tag ไหน ไม่ใช่ "ตัวล่าสุดบน main"
- [ ] artifact ตัวก่อนหน้ายังเก็บไว้และเรียกกลับมาได้
- [ ] เนื้อหาการเปลี่ยนแปลงรอบนี้เป็นเรื่องที่เกี่ยวข้องกัน ไม่ได้พ่วงของอื่นมาด้วย

## 3. แผนถอยกลับ

- [ ] รู้วิธีถอยกลับ เขียนเป็นขั้นตอนแล้ว
- [ ] **เคยลองจริงแล้ว** บนเส้นทางเดียวกันนี้ — ไม่เคยลอง = NO-GO
- [ ] รู้ว่าใช้เวลากี่นาที
- [ ] การเปลี่ยนโครงสร้างข้อมูลถอยกลับได้ หรือระบุชัดว่าถอยไม่ได้และยอมรับแล้ว

## 4. สภาพแวดล้อมและการตั้งค่า

- [ ] ตัวแปรสภาพแวดล้อมที่ต้องใช้มีครบและถูกต้องในปลายทาง
- [ ] ความลับไม่ได้อยู่ในโค้ดหรือใน log
- [ ] การย้ายโครงสร้างข้อมูลรันแล้วหรือมีลำดับที่ชัดเจนว่ารันเมื่อไหร่
- [ ] ข้อมูลสำรองล่าสุดมีอยู่จริงและกู้คืนได้

## 5. แผนเฝ้าดู — ตกลงก่อนปล่อย ไม่ใช่หลังปล่อย

- [ ] รู้ว่าจะดูสัญญาณอะไร ระบุชื่อได้
- [ ] มีเกณฑ์ตัวเลขว่าเท่าไหร่คือต้องถอยกลับ
- [ ] รู้ว่าใครเฝ้า และเฝ้านานเท่าไหร่
- [ ] คนคนนั้นว่างจริงในช่วงเวลานั้น

## 6. จังหวะเวลา

- [ ] ไม่ใช่ช่วงที่ไม่มีใครรับมือได้ถ้าพัง
- [ ] ผู้ใช้ที่ได้รับผลกระทบรู้ล่วงหน้าแล้ว ถ้าจำเป็น

## 7. บันทึกการปล่อย

- [ ] เขียนบันทึกการเปลี่ยนแปลงสำหรับผู้ใช้แล้ว
- [ ] ระบุสิ่งที่ยังพังอยู่และยอมปล่อยไปก่อนแล้ว
- [ ] เตรียมออกเอกสาร `REL-XXX-001` ลงทะเบียนแล้ว

| คำตัดสิน | GO / GO WITH CONDITIONS / NO-GO |
| ผู้ตัดสิน | [ชื่อ] |
| วันเวลา | YYYY-MM-DD HH:MM |
